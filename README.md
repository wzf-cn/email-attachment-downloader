# 邮件接收管理 · MailKit Windows

基于 MailKit / MimeKit 的 Windows 桌面软件。支持多邮箱接入、按组下载、学号与主题校验、自动回复、异常停收与管理员重置。

这是依赖 MailKit 的独立应用，不是 MailKit 官方产品或其源代码分支。

## 运行

右上角“意见反馈”可填写问题或建议，保存为本地文本（默认 `%LOCALAPPDATA%\MailIntake\Feedback`），或复制内容并打开 Gitee Issues 页面。用户需在网页中新建 Issue 并确认提交，软件不会自动上传反馈，也不附带邮箱配置、邮件或日志。

异常通知按一轮检查汇总：检查过程中保留逐条日志和审计记录，不逐封弹出提醒；本轮结束（含暂停）时，只弹出一条异常总数提醒。无异常不弹出，退出软件时不弹出。同一封邮件可能产生多条不同异常，统计的是提示条数而非邮件封数。

安装完成页提供默认勾选的“立即运行邮件接收管理”：点击“完成”后启动软件；取消勾选则只结束安装。静默安装不自动启动。

推荐运行 `MailIntake-Setup-1.0.0.exe` 安装包，按向导安装到当前 Windows 用户目录，无需管理员权限。安装后从开始菜单“邮件接收管理”启动。后续直接运行新版安装包覆盖安装；如果软件正在运行，会询问是否退出再继续，等待最多 60 秒，不强制结束进程。

卸载：Windows“设置 → 应用 → 已安装的应用 → 邮件接收管理 → 卸载”，或开始菜单中的“卸载”。卸载仅移除安装包提供的程序文件、快捷方式及对应启动项，保留 `%LOCALAPPDATA%\MailIntake` 下的配置和记录，以及用户指定的下载目录。重新安装后在同一 Windows 用户下可以继续使用。未保存的界面修改需在退出前保存。

构建安装包：先运行 `scripts/build.ps1`，再运行 `scripts/build-installer.ps1`（使用 NSIS 3.12，可通过 `-MakeNsis` 指定编译器）。安装版后续应使用安装包升级，以保持卸载文件清单一致；下述 `Update.cmd` 仅用于便携版。

Windows x64 发布包解压后运行 `MailIntake.exe`，无需安装 Python 或 .NET 运行时。保留解压目录中的所有文件。

1. 点击 **绑定邮箱**，填写 IMAP/POP3 与 SMTP 地址、端口及邮箱授权码。新建邮箱填写 QQ、163、126 地址并离开输入框后，自动填入对应 SMTP 默认值；收信参数需单独确认。
2. 选中邮箱，点击 **新增规则**，为每组关键词或结构校验明确指定下载目录。
3. 可先 **测试连接（不发信）**，然后确认开始日期与回复内容，点击 **保存并开始**。
4. 勾选登录启动后，当前 Windows 用户登录时自动运行。关闭窗口会转到托盘；右键托盘或点击退出软件才能结束。

授权码在本机界面输入。连接测试只验证接收与 SMTP 登录，不发送测试邮件。配置发生变更后，只有保存才会应用到后续轮次。

SMTP 默认配置：QQ 为 `smtp.qq.com`，163 为 `smtp.163.com`，126 为 `smtp.126.com`，均使用端口 `465` 和 `SSL/TLS`。已有邮箱和手动修改的参数不会自动覆盖；可选择服务商后点击“应用所选 SMTP 默认值”，再保存。此操作仅设置发信参数。

这些 SMTP 参数已对照 [Thunderbird ISPDB](https://github.com/thunderbird/autoconfig/tree/master/ispdb) 与 [Nodemailer](https://github.com/nodemailer/nodemailer/blob/master/lib/well-known/services.json) 一致；配置一致不代表已通过真实账户收发测试。

## 更新软件

将新版解压到一个独立文件夹，双击其中的 `Update.cmd`，选择原软件所在目录。检测到原软件正在运行时，询问是否退出并继续更新；选择“否”不修改文件，选择“是”请求原软件安全退出，等待当前处理结束后再替换程序。尚未保存的界面修改需先保存。等待超过 60 秒则取消本次文件替换，不强制结束进程。

首次从不支持自动退出的旧版本升级时，需要从托盘手动退出一次；安装本版后，后续更新支持自动退出。更新只替换发布清单内的程序文件，保留用户目录、数据库以及下载内容，失败时尝试恢复原程序。更新成功后从原位置启动软件。直接用解压工具覆盖不会触发本提示。

## 主题规则

### 规则模板

选中已有规则后点击“保存为模板”，或在规则编辑窗口点击同名按钮。模板默认保存在 `%LOCALAPPDATA%\MailIntake\RuleTemplates`，也可选择其他位置，文件可复制给其他电脑使用。软件更新和卸载不会删除默认模板目录。

后续选中要使用的邮箱，点击“从模板新增”，选取模板。主题结构、关键词示例、下载选项、大小限制、附件存放方式、自动回复等都会预填；用户主要修改本次主题相关内容，重新选择下载目录、导入名单或填写固定秘钥。保存后点击“保存并开始”应用。新规则与模板独立，修改其中一条不会影响模板或其他规则。

模板不保存旧名单、固定秘钥或下载目录；规则名称、主题示例和自定义回复文字会保留，分享模板前请检查其中的业务信息。若需要修改模板，可在规则编辑窗口再次“保存为模板”并选择原文件覆盖。

“所有附件集中到本组目录的‘全部附件’文件夹”：勾选后附件集中存放，不勾选则按邮件分别存放（默认）。集中存放时文件名带主题、邮件编号和唯一编号，避免同名覆盖；每封邮件仍有正文和记录目录，其中“附件位置.txt”及元数据记录实际附件路径。旧文件不移动，需要勾选重新导出应用到历史邮件。同一邮件命中同目录的多条规则且存放方式不同，采用按邮件分别存放。

每组规则可设置“单个附件上限（MB）”，默认 20，范围 1–500（1 MB 按 1024×1024 字节计算）。等于上限仍导出，超过则在“附件跳过记录.json”及元数据中记录文件名、实际大小和原因，并在异常与审计中提示。其他未超限附件及所选正文仍正常导出；包含超限附件的完整 EML 不保存。若启用成功回复，本次改为说明有超限附件未保存，避免误报全部收到。同目录多规则取最严格的上限。

目前单附件限制在接收并解析邮件后执行，限制落盘保存，并不节省该邮件的网络下载量。主界面“邮件上限”仍在读取邮件内容前判断，可用来拦截整封大邮件；云附件目前只记录链接，不自动下载。

识别到云附件链接时，除单封邮件目录中的链接文件外，还会自动更新本组下载目录下的“云附件汇总.csv”，可用 Excel 打开查看主题、发件人、时间、文件夹及链接。汇总表根据该目录中的链接记录重新生成，不用于手工编辑；链接状态为“尚未下载”，不会误报文件已下载。

每组规则可独立勾选“下载正文”“下载附件”“保存原始邮件 EML”，默认全选，旧配置保持原行为。EML 包含完整正文和随信附件；如果不需要这些内容的副本，也应取消 EML。三项全不选时仅导出元数据记录。同一邮件命中多个规则且目录相同时，合并各规则勾选的内容。选项控制导出文件，收信解析和已启用的异常检查仍会读取邮件内容；修改后需重新导出才能应用到历史邮件，不会删除旧文件。

“主题中需填写的信息”填写信息名称，例如“姓名”，不是某位学生的姓名。固定开头为“工程实践”、分隔符为“-”、信息名称为“姓名”、结尾使用学号名单时，学生的主题应为“工程实践-张三-00123”。多个信息名称可写“姓名,班级”，对应“工程实践-张三-一班-00123”。

导出子目录使用“邮件主题_时间_短编号”，保留中文便于查找。除普通附件外，也提取内嵌文件及未注明 attachment 的二进制内容。QQ 超大附件可能仅包含在线链接，文件本身不在 EML 中：此时单独生成“云附件下载链接.txt”，需要在浏览器中登录下载；无随信附件时生成“附件说明.txt”。软件不会自动访问邮件中的任意网络地址。

勾选“忽略之前的记录，重新导出（仅本次，不回复）”，再点击“立即检查”或“保存并开始”。本次按已保存的邮箱开始日期及规则重新扫描，保留旧导出文件夹，建立新的可读目录，并更新归档列表的目录。此操作不重复回复、不增加主题错误次数、不解除停收、不改变之前的处理状态；本轮不受常规 200 封限制，仍受邮件大小限制，可点击暂停。中途暂停后需重新勾选再运行；软件不会自动续跑这次重新导出。

示例：`工程实践-张三-20260001`

| 配置项 | 示例 |
| --- | --- |
| 模式 | 结构校验 |
| 固定开头 | 工程实践 |
| 分隔符 | - |
| 中间字段 | 姓名 |
| 结尾校验 | 名单 |
| 触发关键词 | 工程实践,实践提交 |
| 本组目录 | 用户明确选择 |

结构为固定开头、一个或多个非空中间字段、结尾学号或秘钥。中间字段用逗号分隔；字段值不能包含分隔符。不支持任意正则或可选字段。除名单姓名外，其他字段仅验证数量、顺序和非空，不判断其业务含义。

任意关键词命中就进入结构校验；关键词留空时使用固定开头。关键词忽略大小写，固定开头、姓名及结尾凭据严格匹配。无关邮件不回复。也可使用普通关键词模式。

**名单导入：**CSV 第一列学号/秘钥，第二列可选姓名。保留前导零，支持 UTF-8 和 GB18030。模板见 `examples/roster.csv`。导入名单是快照，不会跟踪源文件自动同步。如果结构字段含“姓名”，且名单提供姓名，会核对对应关系。

完整命中多组时保存到所有匹配组，同目录一次；仅按首个完整匹配规则决定回复，没有完整匹配则按首个部分匹配规则。用“上移”调整优先级。

## 自动回复与停收

- 第 1～5 次错误统一回复：**主题的格式或内容不符合要求**。
- 第 6 次错误记录异常，尝试发送一次 **请联系管理员重新开放接收** 通知，此后停止处理该发件邮箱所有邮件，包括正确主题。
- 管理员在 **管理员 · 停收与重置** 选择具体发件邮箱恢复，错误次数清零，历史记录保留。
- 暂停期间被本软件识别并跳过的邮件不会补处理，恢复后请重新发送。未被软件扫描到的历史来信，在恢复后仍按开始日期检查。
- 计数按发件邮箱跨所有接收邮箱合计，重启保留；同一接收邮箱同一 UID 不重复计数，不同接收邮箱中的同一群发邮件分别计一次。
- 停收通知独立于普通回复开关；回复结果不确定时不自动重发，停收状态不撤销。

**停止处理不等于邮件服务器拒收：**程序仍需读取邮件头识别发件邮箱；不修改服务商黑名单，不删除邮件，不阻止邮件到达 QQ 收件箱。

每小时全局回复上限默认 100，超过时记录“达到回复限额”，不自动补发；该上限也适用于停收通知。邮件大小默认上限 30 MB，超过时记录异常且不下载。每轮最多处理 200 封已匹配或停收邮件。这些是资源限制，不是发件人认证。

发送状态“服务器已接受”仅表示 SMTP 接受；“发送中或中断待核实”“结果不确定”都需人工核对，不自动重发。异常退出发生在错误登记之后、发送登记之前时，回复可能未发出，应通过异常和回复记录核实。

## 归档与异常

保存原始 `.eml`、纯文本正文、HTML 正文（如有）、附件与 `metadata.json`。包含发件人、主题、收件时间、发送时间、保存时间和路径。HTML 和附件不会自动打开或解压。未通过主题校验只读邮件头，不下载附件。

同主题、不同发件邮箱的正文或附件变化会记录异常。正文前 20,000 字符采用字符二元组相似度，低于 55% 提醒；附件比较哈希，不判断 Word/PDF/图片语义。最多对比最近 100 条同主题记录。提醒仅供管理员核对。

## 数据与权限

- 本机数据：`%LOCALAPPDATA%\MailIntake`。配置、名单、凭据及数据库不提交 Git。
- 邮箱授权码使用 Windows DPAPI，绑定当前 Windows 用户。主题秘钥、名单和下载材料不加密。
- 管理员入口目前依赖本机 Windows 用户的访问权限，没有独立管理员登录或角色系统。
- 基于邮件 From 的计数与停收无法防止伪造或更换地址。尚未提供可信 SPF/DKIM/DMARC 校验及地址绑定验证。
- IMAP 只读，不改变已读状态。POP3 不删除邮件，依赖 UIDL 去重；POP3 不能获取可靠服务器收件时间，开始日期按邮件 Date 头筛选。
- 支持 SSL/TLS 与强制 STARTTLS；不允许关闭证书验证。此版尚未提供 OAuth 登录界面，不能据 MailKit 底层支持 OAuth 就认为应用已支持。

## 从 Python 原型迁移

退出原 Python 软件，打开新版点击 **导入旧版配置**，选择原 `%LOCALAPPDATA%\KeywordMailDownloader\config.json`。导入账号、规则，以及同目录数据库中的已处理与停收状态；源文件不修改。

旧归档、旧异常和旧回复明细仍在原目录与数据库，本版仅迁移必要去重标记和停收计数，避免重复回复；旧历史明细可继续从原版导出。相同邮箱不会重复添加。请核对规则后再保存开始。

## 开发与构建

需要 .NET 10 SDK。依赖版本和锁文件随源码提交。

```powershell
dotnet build src/MailIntake.Desktop/MailIntake.Desktop.csproj
dotnet run --project tests/MailIntake.Tests/MailIntake.Tests.csproj
./scripts/build.ps1
```

若 SDK 不在 PATH：`./scripts/build.ps1 -Dotnet '实际路径\dotnet.exe'`。

源码仓库：<https://gitee.com/wzFeel/email-attachment-downloader>

`src/MailIntake.Core`：校验、MailKit 协议接入、持久化、归档与收件策略。
`src/MailIntake.Desktop`：Windows Forms 界面、托盘、自启动、DPAPI、旧版迁移。
`tests/MailIntake.Tests`：不连接外部邮箱的自动化业务测试。

## 交付边界

当前为 0.1 桌面版本。尚未用真实 QQ 邮箱授权码收发、未验证机器重启后的登录启动，也未做代码签名或安装器。离线测试和界面检查不能替代真实邮箱兼容性验证。

主项目尚未选择公开开源许可证；未因此授予第三方复制或分发本项目的许可。第三方组件各自的许可与声明见 `THIRD_PARTY_NOTICES.md` 和 `licenses/`，MailKit 的 MIT 许可不自动覆盖本应用的自有代码。
